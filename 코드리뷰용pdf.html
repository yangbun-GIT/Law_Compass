1. 최종 판정

현재 LawCompass는 다섯 구조 문서의 핵심 방향을 충족한다. 단, 완전한 표준 MCP 서버/클라이언트나 독립 Multi-Agent 프로세스가 아니라, Docker Compose 기반 경량 MSA형 모노레포 위에 Agent 내부 role-based specialist pipeline, MCP-like tool registry/executor, Task-Plan-Goal packet/trace 구조를 결합한 형태로 설명해야 한다.

구조 기준 만족문서-코드 싱크 통과Agent 계약 테스트 통과SRP watchlist 경고 존재표준 MCP 도입 보류

교수님께 말할 핵심: 표준 MCP를 붙였다고 과장하지 않고, 현재 문제에 맞게 내부 MCP-like executor와 Agent packet 구조를 먼저 안정화했다. 외부 tool server나 다중 host 재사용 요구가 생기면 표준 MCP로 확장할 수 있게 pilot 계약을 남겼다.

4. Agent 내부 동작 방식

  1. 자연어, structured facts, 영상 metadata를 합쳐 분석 가능한 fact로 정리한다.
  2. 직접 충돌 대상을 먼저 판정해 KNIA 대분류를 고정한다.
  3. 영상 관찰값은 후보/확인/확정/충돌/무시 상태로 분리한다.
  4. 대분류가 정해지면 다른 대분류 chart/RAG가 최종 결과에 섞이지 않게 party guard를 적용한다.
  5. KNIA structured chart를 우선 검색하고 같은 chart 또는 같은 대분류 RAG만 사용한다.
  6. 과실비율은 base fault, final fault, range, applied/unknown adjustment, conditional outcome으로 분리한다.
  7. 사용자 화면에는 raw trace와 내부 key를 숨기고 참고/조건부/추가 확인 필요 표현으로 변환한다.
핵심은 AI가 과실 숫자를 임의 생성하지 않는다는 점이다. 숫자는 구조화 KNIA chart와 deterministic adjustment policy를 우선하고, 근거가 부족하면 reference-only 또는 needs-review로 낮춘다.

8. 발표용 설명 흐름

  1. 문제: 교통사고 사용자는 사고 사실, 영상, 보험 기준, KNIA 기준을 따로 확인해야 한다.
  2. 구조: 화면, API, 영상 처리, AI 판단, DB/RAG를 컨테이너 단위로 분리한 경량 MSA형 모노레포다.
  3. 핵심 설계: 사고 대분류와 직접 충돌 대상을 먼저 고정해 잘못된 KNIA 기준 혼선을 막았다.
  4. RAG: 구조화 KNIA chart를 우선 선택하고, 선택된 chart 또는 같은 대분류의 RAG chunk만 검색한다.
  5. Agent: 완전 독립 Agent process가 아니라 역할 기반 specialist result와 consensus packet을 붙인 내부 pipeline이다.
  6. MCP: 표준 MCP runtime은 보류하고, 내부 MCP-like registry/executor로 schema, scope, timeout, failure packet을 관리한다.
  7. 품질: finality, 조건부 결과, 표시 sanitizer, regression test로 근거 없는 확정 판단을 제한한다.
  8. 한계: 일부 중심 파일이 크며, 표준 MCP/독립 Agent process/Kubernetes/서비스별 DB 분리는 후속 과제다.

9. 교수님 예상 질문과 답변

Q. 왜 완전한 MSA가 아니라 경량 MSA형 모노레포인가?

현재 규모에서는 서비스별 독립 저장소와 DB 분리보다 컨테이너 단위 책임 분리와 명확한 API/DTO 계약이 더 실용적이다. Frontend/Gateway/Agent/Worker/PostgreSQL/Redis는 분리했지만 운영 복잡도를 줄이기 위해 Docker Compose 기반 단일 배포 단위로 유지했다.

Q. MCP를 구현한 것인가?

표준 MCP 서버/클라이언트를 구현한 것은 아니다. 내부 MCP-like tool registry/executor를 구현했고, 표준 MCP 도입 조건과 read-only pilot adapter 설계를 문서화했다. 현재는 내부 executor가 production source of truth다.

Q. AI가 과실비율을 마음대로 생성하지 않는가?

과실 숫자는 구조화 KNIA chart와 deterministic adjustment policy를 우선한다. LLM은 근거 설명과 요약을 보조하고, base fault가 없거나 review_required이면 reference-only 또는 needs-review로 낮춘다.

Q. 영상 분석이 사고 결론을 바로 내리는가?

아니다. Worker는 프레임과 객체/장면 관찰 후보를 만들고, Agent는 이를 사용자 입력, KNIA, 법령 근거와 함께 조율한다. 보행자나 자전거가 화면에 보인다는 이유만으로 사고 당사자로 승격하지 않는다.

Q. 현재 가장 큰 리스크는?

일부 핵심 조립 파일의 규모, KNIA/판례 원문 coverage, GitHub Pages가 정적 프론트만 제공한다는 배포 한계다. 이들은 모두 문서와 후속 백로그에 분리해 두었다.
